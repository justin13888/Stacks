# stacks — agent guide

Self-hosted media tracker. Users authenticate via OIDC, browse cameo-indexed
metadata (TMDB + AniList), maintain watch state in PostgreSQL, and stream
through a registered Beam media server with HMAC-verified webhooks. The HTTP
surface is a Salvo-built JSON REST API with an auto-generated OpenAPI 3.1
spec; the reference web client is a Bun + Vite + React 19 SPA driven by a
TanStack Router/Query stack with an orval-generated typed client.

## Tech stack

- **API:** Rust 2024, `cargo` workspace. Salvo 0.77 with `oapi`, `cors`,
  `jwt-auth`, `affix-state`, `logging`. Async via `tokio` (full). Errors via
  `thiserror` / `eyre` / `color-eyre`. Logs via `tracing` +
  `tracing-subscriber` (JSON). Metrics via `metrics` +
  `metrics-exporter-prometheus`.
- **Database:** PostgreSQL >= 18, SeaORM 1 (`sqlx-postgres`,
  `runtime-tokio-rustls`). Migrations live in `core/migration` and run at API
  startup.
- **Crypto / auth:** `jsonwebtoken` (HS-signed JWTs), `argon2` (API-token
  hashing), `aes-gcm` (AES-256-GCM at-rest for streaming-server credentials),
  `hmac` + `sha2` (Beam webhook verification).
- **Metadata SDK:** [cameo](https://github.com/justin13888/cameo) as a
  workspace dep, `default-features = false, features = ["tmdb", "anilist"]`.
  The `cache` feature is intentionally off — `rusqlite`'s `libsqlite3-sys`
  collides with the copy `sqlx` pulls in via SeaORM. Leave it disabled.
- **Web:** Bun + Vite + React 19, TanStack Router + Query, Tailwind 4,
  `motion`, `@dnd-kit`, `recharts`. Typed API client is generated by
  `orval` from the OpenAPI spec the API emits.
- **Tooling:** `just` for the task runner, `lefthook` for git hooks, `biome`
  for web formatting / linting, `cargo-llvm-cov` for coverage (CI gates at
  80% line coverage on `api` + `core`).
- **No CLI.** Earlier scaffolding had one; it was dropped. Operator surface
  is the admin API.

## Key conventions

- **Canonical media id.** Every `cameo_media_id` column stores a self-describing
  `<provider>:<kind>:<numeric>` string — e.g. `tmdb:movie:550`,
  `anilist:tv:21`. Episode ids extend with `:<season>:<episode>`. cameo's
  `provider_id` only carries provider + numeric; the kind is folded in at
  Stacks's edge because cameo routes movies and TV through separate calls.
  Parse with `MediaId::parse` / `EpisodeId::parse`; build with `from_cameo`
  + a known `MediaKind`. See [`core/src/media/id.rs`](core/src/media/id.rs).
- **Opaque cursor pagination.** Listing endpoints take `?cursor=…&limit=…`.
  Default limit 50, hard cap 200. Cursors are base64url-encoded page numbers
  (cameo's pagination is page-based; the cursor hides that). A bad cursor
  silently returns page 1. See [`core/src/pagination.rs`](core/src/pagination.rs).
- **Server credentials at rest.** Streaming-server API keys are
  AES-256-GCM encrypted with a key derived from `WW_SECRET_KEY` via
  `crypto::derive_key` (SHA-256, domain-separated). Decryption happens only
  when constructing a `BeamConnector` for an outbound call.
- **`JobContext`** carries the `DatabaseConnection`, shared
  `Arc<CameoClient>`, and the 32-byte encryption key into every background
  job handler. Webhook handlers and admin handlers reconstruct the
  encryption key from `state.config.auth.secret_key` via `crypto::derive_key`
  so they share the same domain-separated derivation.
- **Errors at the API edge.** Each module has its own thiserror-derived
  error enum mapped to HTTP statuses via `salvo::Writer`. Unexpected errors
  collapse into [`api::error::InternalError`](api/src/error.rs) which logs
  via `tracing::error` and emits a fixed `{ "error": { "code":
  "INTERNAL_ERROR", "message": "An internal error occurred" } }` body. Use
  the `crate::internal!(e)` macro inline.
- **OpenAPI is auto-generated.** Every handler must be annotated
  `#[salvo::oapi::endpoint(tags("…"), summary = "…")]` and its request /
  response DTOs derive `ToSchema` / `ToParameters`. The spec is built by
  walking the router in [`api/src/app.rs`](api/src/app.rs); the
  `gen-openapi` binary dumps it without needing a DB.
- **Auth.** OIDC only. JWT bearer for sessions (`AuthMiddleware` validates
  HS-signed access tokens, falls back to API-token lookup). Admin-only
  routes additionally pass through `AdminGuard` (`role == "admin"`).
  Webhook routes are public — HMAC signatures are their authentication.
- **Conventional commits.** Recent log: `feat`, `fix`, `chore`, `docs`, `test`,
  with optional scopes `(api)`, `(core)`, `(web)`.

## Build / test

All tasks run from the workspace root.

```bash
just lint       # cargo fmt --check + clippy -D warnings + biome
just test       # cargo test (api + core) + bun test (web)
just coverage   # cargo llvm-cov, 80% line minimum
just codegen    # dump OpenAPI -> web/openapi.json, run orval
just gen-openapi  # spec to stdout

cargo run -p stacks-api                 # start the server (needs env)
docker compose -f compose.dependencies.yaml up -d   # local Postgres
```

Per-package shortcuts (`format-api`, `lint-core`, `test-web`, …) exist in
the [Justfile](Justfile).

## Where to start

### Adding a new API endpoint

1. **Domain logic in `core/`.** Add or extend a service in the relevant
   module (`core/src/<area>/service.rs`); keep repo functions thin (SeaORM
   queries only).
2. **Migration (if schema changes).** Add `m0NN_*.rs` under
   `core/migration/src/`, register it in `lib.rs`. Migrations auto-run on
   API startup.
3. **DTOs + error.** In `api/src/<area>/dto.rs` derive `ToSchema` /
   `ToParameters` on every request/response; in `api/src/<area>/error.rs`
   add a `thiserror` enum implementing Salvo's `Writer` to map onto HTTP
   statuses.
4. **Handler.** `#[salvo::oapi::endpoint(tags("…"), summary = "…")]`
   function in `handlers.rs`; pull `AppState` from the `Depot`, construct
   the service, return `Result<Json<Response>, Error>`.
5. **Wire it up.** Add the route in `api/src/<area>/mod.rs` (`Router::with_path("…").get(handlers::…)`),
   and make sure the area router is `.push`-ed into the right branch of
   [`api/src/app.rs`](api/src/app.rs) (`public_router` for unauthenticated,
   the auth-hooped branch for normal users, the admin-hooped branch for
   admin-only). Don't forget to add it to `build_router_stub` too, or the
   OpenAPI spec won't include it.
6. **Regenerate the client.** `just codegen` updates `web/openapi.json` and
   the orval-generated typed client.

### Adding a new job type

1. Add a variant to `repo::JobType` in
   [`core/src/jobs/repo.rs`](core/src/jobs/repo.rs) with `as_str` / `parse`
   handling.
2. Create `core/src/jobs/handlers/<name>.rs` with a `Payload` struct
   (`Serialize` + `Deserialize`) and an `async fn handle(ctx: &JobContext,
   payload: Payload) -> Result<(), JobError>`.
3. Register it in `core/src/jobs/handlers/mod.rs`.
4. Wire dispatch into the `match job_type { … }` block in
   [`core/src/jobs/runner.rs`](core/src/jobs/runner.rs).
5. Enqueue with `jobs_repo::enqueue_job(db, jobs_repo::build_job(JobType::Foo,
   Some(payload), max_attempts))`. The runner picks it up within
   the polling interval (10s by default); failures back off with
   `30s × 2^attempts`, capped at 1h.

### Adding a new notification channel

1. Implement
   [`core/src/notifications/channels/mod.rs::NotificationChannel`](core/src/notifications/channels/mod.rs)
   in a new file under `channels/`. The trait is async and gets the
   rendered notification + the user's per-channel config JSON.
2. Re-export from `channels/mod.rs`.
3. Add a branch in `NotificationService::dispatch`'s `match
   channel.channel_type.as_str()` in
   [`core/src/notifications/service.rs`](core/src/notifications/service.rs).
4. Document the config shape (the existing channels declare a
   `ChannelConfig` struct that `serde_json::from_value`s the stored JSON —
   follow the same pattern).

### Other common edits

- **New env var.** Add to `FileXxx` in
  [`core/src/config/file.rs`](core/src/config/file.rs), then layer it in
  [`core/src/config/env.rs`](core/src/config/env.rs) via `require` /
  `optional` / `optional_u64`. Update the table in the README and
  `docs/DEPLOY.md`.
- **New migration.** `m0NN_*.rs` in `core/migration/src/`; add to
  `Migrator::migrations` in `lib.rs`. They run idempotently on every
  startup via `MigratorTrait::up`.
- **Frontend route / page.** TanStack Router with file-based routing under
  `web/src/router/`. The data hooks live in `web/src/api/` (orval-generated)
  and `web/src/hooks/`.
