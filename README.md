# stacks

Self-hosted media tracking service. Track what you watch across movies, TV, and
anime; keep your scores, lists, and history in your own PostgreSQL database;
connect a Beam streaming server for one-click playback; and import existing
data from MAL / TMDB.

stacks delegates metadata to [cameo](https://github.com/justin13888/cameo)
(unified TMDB + AniList client) and stores only opaque references and your
personal watch state. If every upstream provider went dark tomorrow, your
scores, lists, and history would remain intact.

## Highlights

- **OIDC-only authentication.** Bring your own provider (Authelia, Authentik,
  Keycloak, Dex, etc.); no local password store. Short-lived JWT access tokens,
  rotating refresh tokens, and opaque API tokens (`stk_…`) with `read` /
  `write` / `admin` scopes.
- **cameo-backed browsing.** Search, media detail, seasons, episodes,
  recommendations, and discover feeds (trending / popular / top-rated for both
  movies and TV) overlaid with the current user's watch state.
- **Watch tracking.** Per-title status (`plan_to_watch`, `watching`, `on_hold`,
  `completed`, `dropped`, `rewatching`), 0-100 score, episode-level progress,
  append-only history, custom + smart lists, tags, blocklist.
- **Beam streaming connector.** Library sync (matched to canonical media ids by
  external provider ids), live availability lookup, deep-link / playback URLs,
  and HMAC-SHA256 verified inbound webhooks for library and playback events.
- **Import / export.** Import from MyAnimeList XML, MAL JSON, and TMDB JSON via
  a background job; export your data as JSON or CSV.
- **Background jobs.** PostgreSQL-backed queue with exponential backoff,
  attempt budget, and an admin retry endpoint. Periodic Beam library sync is
  driven by the same runner.
- **Notifications.** Per-user webhook and Apprise channels with subscription
  preferences per event type (new episode, available on Beam, upcoming
  release, import completed).
- **Observability.** JSON structured logs (`tracing`), Prometheus `/metrics`
  endpoint, liveness + readiness probes.
- **Hardening.** Configurable CORS allowlist, per-IP rate limit on `/auth/*`
  (30 req/min), security headers (`X-Content-Type-Options`, `X-Frame-Options`,
  CSP, `Referrer-Policy`), encrypted-at-rest streaming-server credentials
  (AES-256-GCM keyed off `WW_SECRET_KEY`).

## Architecture

Cargo workspace plus a Bun-managed React frontend:

```
/
├── api/         # stacks-api — Salvo HTTP server (binary)
│                # Routers, middleware, DTOs; thin handlers over stacks-core
├── core/        # stacks-core — domain library (auth, media, jobs, streaming,
│                # notifications, stats, import/export, crypto, config)
│   └── migration/  # SeaORM migrations (PostgreSQL)
└── web/         # Bun + Vite + React 19 + TanStack Router/Query
                 # API client generated by orval from /api-docs/openapi.json
```

`stacks-api` exposes a single port (default `8095`). On startup it loads
configuration, opens a PostgreSQL connection via SeaORM, runs pending
migrations, installs the Prometheus recorder, spawns the background
[`JobRunner`](core/src/jobs/runner.rs) and the periodic Beam-sync scheduler,
then serves the Salvo router. In debug builds it additionally serves the
OpenAPI 3.1 spec at `/api-docs/openapi.json` and a Scalar UI at `/scalar`.

## Quick start — development

PostgreSQL 18 is the only external dependency. The repo ships a compose file
for it.

```bash
# 1. Start PostgreSQL
docker compose -f compose.dependencies.yaml up -d

# 2. Configure the API. Copy api/.env.example and fill in the values below
#    (in particular a 32+ byte WW_SECRET_KEY and a TMDB API key).
cp api/.env.example api/.env
$EDITOR api/.env

# 3. Run the API. Migrations apply automatically on startup.
cargo run -p stacks-api

# 4. In another terminal, run the web dev server
cd web
bun install
bun run dev
```

Minimum env for local dev:

```bash
WW_DATABASE_URL=postgres://stacks:stacks@localhost:5432/stacks
WW_SECRET_KEY=$(openssl rand -hex 32)
WW_TMDB_API_KEY=your-tmdb-v4-bearer-or-v3-key
WW_OIDC_ISSUER=https://auth.example.com
WW_OIDC_CLIENT_ID=stacks
WW_OIDC_CLIENT_SECRET=...
WW_OIDC_REDIRECT_URI=http://localhost:5173/auth/callback
```

OIDC is required — there are no local accounts. Point `WW_OIDC_*` at your
provider before first login.

## Quick start — production with Docker Compose

```bash
# Generate a secret key (32 bytes, hex-encoded — fits the AES-256-GCM derivation)
export WW_SECRET_KEY=$(openssl rand -hex 32)

# Set the rest in your shell or a .env loaded by `docker compose`
export WW_TMDB_API_KEY=...
export WW_OIDC_ISSUER=https://auth.example.com
export WW_OIDC_CLIENT_ID=stacks
export WW_OIDC_CLIENT_SECRET=...
export WW_OIDC_REDIRECT_URI=https://stacks.example.com/auth/callback

docker compose up -d
```

`compose.yaml` is a one-liner that includes `compose.dependencies.yaml`
(PostgreSQL) and `compose.stacks.yaml` (the API on port 8095 and the static
web build on port 3000). Put a TLS reverse proxy (Caddy, Nginx, Traefik) in
front of both.

See [`docs/DEPLOY.md`](docs/DEPLOY.md) for the full production guide.

## Configuration

All settings come from environment variables, optionally layered over a
`config.toml` whose path is taken from `WW_CONFIG_FILE` (default `config.toml`
in the working directory). Env vars take precedence over the file; required
values must be set somewhere or the API refuses to start.

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `WW_DATABASE_URL` | yes | — | PostgreSQL DSN (e.g. `postgres://user:pass@host:5432/db`). |
| `WW_SECRET_KEY` | yes | — | Signs JWTs and (via SHA-256 derivation) the AES-256-GCM key for streaming-server credentials. Generate with `openssl rand -hex 32`. |
| `WW_TMDB_API_KEY` | yes | — | Passed to cameo for TMDB access (v3 key or v4 bearer). |
| `WW_OIDC_ISSUER` | yes | — | OIDC provider base URL; discovery uses `<issuer>/.well-known/openid-configuration`. |
| `WW_OIDC_CLIENT_ID` | yes | — | OIDC client id. |
| `WW_OIDC_CLIENT_SECRET` | yes | — | OIDC client secret. |
| `WW_OIDC_REDIRECT_URI` | yes | — | Redirect URI registered with the provider (typically the web app's `/auth/callback`). |
| `WW_BIND` | no | `0.0.0.0:8095` | Listen address. |
| `WW_LOG_LEVEL` | no | `info` | Subscriber filter — anything `tracing_subscriber::EnvFilter` accepts (`trace`, `debug`, `info`, `warn`, `error`, `module=level,...`). |
| `WW_DATA_DIR` | no | `/data` | Base directory; also the parent of the default cameo cache directory. |
| `WW_CAMEO_CACHE_DIR` | no | `${WW_DATA_DIR}/cameo` | Cameo cache directory. Note: cameo's response cache feature is currently disabled in the workspace; this path is reserved for when it is re-enabled. |
| `WW_CORS_ALLOWED_ORIGINS` | no | localhost dev defaults | Comma-separated origin allowlist. A single `*` opens CORS to any origin and logs a warning. Empty list falls back to `http://localhost:{5173,3000}` and the `127.0.0.1` equivalents. |
| `WW_ACCESS_TOKEN_TTL_SECS` | no | `900` | JWT access-token lifetime. |
| `WW_REFRESH_TOKEN_TTL_SECS` | no | `2592000` | Refresh-token lifetime (30 days). |
| `WW_BEAM_SYNC_INTERVAL_SECS` | no | `3600` | How often the scheduler enqueues a `beam_sync` job per enabled server. |
| `WW_CONFIG_FILE` | no | `config.toml` | Optional TOML config path layered under env vars. |

The authoritative list lives in [`core/src/config/env.rs`](core/src/config/env.rs).

## API examples

All requests carry `Authorization: Bearer <jwt_or_api_token>`. The login flow
is OIDC: `POST /api/v1/auth/login` returns a redirect URL; after the provider
sends the user back to `GET /api/v1/auth/callback?code=…&state=…` (with an
`X-Oidc-Nonce` header containing the nonce the client received from `login`),
the API returns an access/refresh token pair.

### Search media

```http
GET /api/v1/media/search?q=evangelion&limit=20 HTTP/1.1
Authorization: Bearer eyJhbGciOi...
```

Response:

```json
{
  "items": [
    {
      "cameo_media_id": "tmdb:tv:30991",
      "title": "Neon Genesis Evangelion",
      "media_type": "tv",
      "year": 1995,
      "poster_path": "...",
      "watch_status": null,
      "score": null,
      "availability": { "available": false, "servers": [] }
    }
  ],
  "next_cursor": "Mg"
}
```

Pagination is opaque: pass the previous response's `next_cursor` as
`?cursor=Mg` to fetch the next page. Cursors are short base64url page tokens.

### Get streaming availability

```http
GET /api/v1/media/tmdb:tv:30991/availability HTTP/1.1
Authorization: Bearer ...
```

```json
{
  "available": true,
  "servers": [
    {
      "server_id": "01HZ...",
      "server_name": "Living Room Beam",
      "quality": "1080p",
      "deep_link": "https://beam.local/library/abc",
      "playback_link": "https://beam.local/api/library/abc/playback"
    }
  ]
}
```

### Start an import

Import endpoints accept base64-encoded source data and enqueue a background
job; `source` is one of `mal_xml`, `mal_json`, `tmdb_json`. `conflict_strategy`
is `skip` (default), `overwrite`, or `merge`.

```http
POST /api/v1/users/me/import HTTP/1.1
Authorization: Bearer ...
Content-Type: application/json

{
  "source": "mal_xml",
  "data_base64": "PG15YW5pbWVsaXN0Pi4uLjwvbXlhbmltZWxpc3Q+",
  "conflict_strategy": "merge"
}
```

```json
{ "job_id": "01HZ...", "status": "pending", "attempts": 0, "error": null }
```

Poll `GET /api/v1/users/me/import/{job_id}` for progress.

### Export

```http
GET /api/v1/users/me/export?format=csv HTTP/1.1
Authorization: Bearer ...
```

Returns a `text/csv` (or `application/json` with `?format=json`) download of
the user's watch-state rows.

The full OpenAPI 3.1 spec is generated from the handlers; in debug builds the
running API serves it at `/api-docs/openapi.json` and an interactive Scalar UI
at `/scalar`. Offline regeneration is `cargo run -p stacks-api --bin
gen-openapi`.

## Troubleshooting

- **`missing required environment variable: WW_DATABASE_URL`** (or
  `WW_SECRET_KEY`, `WW_TMDB_API_KEY`, any `WW_OIDC_*`). The API refuses to
  start without these. Set them in the environment or in a `config.toml` (see
  the configuration table).
- **`failed to install Prometheus recorder`.** The process tried to install
  the global recorder twice. Make sure you are not running another stacks-api
  instance in the same process; this is a startup-only failure.
- **401 from every authenticated route.** Either the JWT has expired (default
  15 min — refresh via `POST /api/v1/auth/refresh`) or the API token does not
  exist / was deleted. Check `WW_SECRET_KEY` is identical to the value used
  when the token was issued; rotating the secret invalidates every JWT.
- **CORS errors from the web app.** Set `WW_CORS_ALLOWED_ORIGINS` to your
  frontend origin (e.g. `https://stacks.example.com`). The default localhost
  dev allowlist does not cover production origins.
- **Webhooks return 401 `INVALID_SIGNATURE`.** The Beam server's `webhook_secret`
  in stacks must match the secret configured on the Beam side. Stacks accepts
  the signature in `X-Beam-Signature` or `X-Hub-Signature-256`, hex-encoded,
  optionally prefixed `sha256=`.
- **`/api/v1/auth/*` returns 429.** The public auth router is rate-limited to
  30 requests per minute per source IP. Behind a reverse proxy, ensure
  `X-Forwarded-For` is set; the limiter uses its first hop.
- **Migrations failed at startup.** Check the PostgreSQL version (>=18) and
  that the role in `WW_DATABASE_URL` can `CREATE TABLE`. Migrations run via
  `migration::Migrator::up`.
