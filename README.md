# stacks

Self-hosted media tracking service. Track what you watch across movies, TV, and
anime; keep your scores, lists, and history in your own PostgreSQL database;
connect a Beam streaming server for one-click playback; and import existing
data from MAL / TMDB.

stacks delegates metadata to [cameo](https://github.com/justin13888/cameo)
(unified TMDB + AniList client) and stores only opaque references and your
personal watch state. If every upstream provider went dark tomorrow, your
scores, lists, and history would remain intact.

## Highlights

- **OIDC-only authentication.** Bring your own provider (Authelia, Authentik,
  Keycloak, Dex, etc.); no local password store. The id_token is verified in
  full (signature, issuer, audience, nonce, PKCE); the browser holds an
  httpOnly session cookie, and scripts use API tokens (`stk_…`) with enforced
  `read` / `write` / `admin` scopes.
- **cameo-backed browsing.** Search, media detail, seasons, episodes,
  recommendations, and discover feeds (trending / popular / top-rated for both
  movies and TV) overlaid with the current user's watch state.
- **Watch tracking.** Per-title status (`plan_to_watch`, `watching`, `on_hold`,
  `completed`, `dropped`, `rewatching`), 0-100 score, episode-level progress,
  append-only history, custom + smart lists, tags, blocklist, and a filterable
  library view.
- **Beam streaming connector.** Library sync (matched to canonical media ids by
  external provider ids), live availability lookup, deep-link / playback URLs,
  and HMAC-SHA256 verified inbound webhooks for library and playback events.
- **Import / export.** Import from MyAnimeList XML, MAL JSON, and TMDB JSON via
  a background job; export your data as JSON or CSV.
- **Background jobs.** PostgreSQL-backed queue with exponential backoff,
  attempt budget, and an admin retry endpoint. Periodic Beam library sync is
  driven by the same runner.
- **Notifications.** Per-user webhook and Apprise channels with subscription
  preferences per event type (new episode, available on Beam, upcoming
  release, import completed).
- **Observability.** JSON structured logs (`tracing`), Prometheus `/metrics`
  labelled by operation on a separate operator port, liveness + readiness
  probes.
- **Hardening.** Per-client rate limit on `/api/v1`, Fetch Metadata CSRF
  refusal plus `SameSite=Lax` cookies, security headers
  (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`,
  `Cache-Control: no-store`), and a CORS allowlist that is empty by default.

## Architecture

Cargo workspace plus a Bun-managed React frontend:

```
/
├── api/         # stacks-api — kynos HTTP server (binary); its OpenAPI 3.1
│                # document is derived from the router (web/openapi.json)
├── core/        # stacks-core — domain library (auth, media, jobs, streaming,
│                # notifications, stats, import/export, crypto, config)
│   └── migration/  # SeaORM migrations (PostgreSQL)
├── tests/e2e/   # a spargen client of web/openapi.json driving a real server
└── web/         # Bun + Vite + React 19 + TanStack Router/Query
                 # API client generated by orval from web/openapi.json
```

`stacks-api` serves the API on one port (default `8095`) and `/metrics` on an
operator port (default `9095`). On startup it loads configuration, opens a
PostgreSQL connection via SeaORM, runs pending migrations, installs the
Prometheus recorder, spawns the background
[`JobRunner`](core/src/jobs/runner.rs), then serves the kynos router,
including its reference at `/api/docs` and its OpenAPI 3.1 document at
`/api/openapi.json`.

## Quick start

Everything runs in containers, including a development identity provider — so a
fresh clone gets you a working login without standing up Keycloak first.

**Prerequisites:** Podman (or Docker) with compose support, [`just`](https://github.com/casey/just),
and a **TMDB v4 read-access token** — the one value you have to supply yourself.
Get one at <https://www.themoviedb.org/settings/api>.

```bash
# 1. Write api/.env from the example, with a freshly generated WW_SECRET_KEY.
just setup

# 2. Paste your TMDB token into api/.env as WW_TMDB_API_KEY.
$EDITOR api/.env

# 3. Build and start Postgres + Dex + API + web.
just up
```

Open <http://localhost:3000>, click **Login**, and sign in with:

| | |
|---|---|
| Email | `dev@stacks.local` |
| Password | `password` |

That account is listed in `WW_ADMIN_EMAILS`, so it is provisioned as an admin
and the `/api/v1/admin/*` routes are available to it.

From there: search for a title, open it, set a status and score — it appears on
**Library**. Lists, tags, stats, import/export and notification channels all work
against live data, and the session survives a page reload.

| Service | URL |
|---|---|
| Web app | <http://localhost:3000> |
| API | <http://localhost:8095> |
| Dex (dev IdP) | <http://localhost:5556/dex> |
| Postgres | `localhost:5432` (`stacks` / `stacks`) |

Other recipes: `just logs [service]`, `just down`, `just nuke` (drops volumes),
and `just up-beam`, which additionally starts a mock Beam server so the
streaming integration can be exercised — see [Streaming](#streaming) below.

> **The bundled Dex is for development only.** Its client secret and password
> are fixed and public, and it is gated behind the `dev-idp` compose profile.
> For anything real, drop the profile and point `WW_OIDC_*` at your own
> provider — see [Using your own OIDC provider](#using-your-own-oidc-provider).

### Container runtime

`just up` auto-detects the runtime, preferring Podman and falling back to
Docker. Override it explicitly if needed:

```bash
just container_engine=docker up
```

All image references are fully qualified (`docker.io/...`) because Podman
refuses unqualified short names.

### Working on the code

For an edit-reload loop, run Postgres and Dex in containers and the API and web
server on the host:

```bash
just dev-up                                   # Postgres only
podman compose --profile dev-idp up -d dex    # Dex only
just dev-api                                  # API on :8095
just dev-web                                  # Vite dev server on :3000, proxying /api
```

`just dev-api` reads `api/.env`. When running the API on the host rather than in
compose, leave `WW_OIDC_INTERNAL_ISSUER` empty — the split-horizon rewrite is
only needed inside the compose network.

Every dev / CI / git-hook command is a recipe in the workspace
[`Justfile`](Justfile); `just --list` shows them all. `just check` is the same
gate CI and the pre-push hook run (format, clippy, typecheck, tests, the OpenAPI client contract).

### Using your own OIDC provider

Stacks is OIDC-only — there is no local password store. To use a real provider,
register a web application with:

- **Redirect URI:** `https://your-stacks-host/auth/callback` (the *web app's*
  route, not the API's — the SPA forwards the code to the API)
- **Scopes:** `openid email profile`

then set `WW_OIDC_ISSUER`, `WW_OIDC_CLIENT_ID`, `WW_OIDC_CLIENT_SECRET`, and
`WW_OIDC_REDIRECT_URI`, and start compose without the `dev-idp` profile
(`docker compose up -d`, rather than `just up`).

Put your own email in `WW_ADMIN_EMAILS` to be provisioned as an admin. Existing
accounts are promoted on their next sign-in, so you can grant admin without
touching the database.

### Streaming

Beam is a separate self-hosted media server. `just up-beam` starts a small mock
of it so the integration is demonstrable locally:

```bash
just up-beam
# Register it (as an admin), then trigger a library sync:
curl -X POST http://localhost:8095/api/v1/admin/servers \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"Mock Beam","server_type":"beam","base_url":"http://mock-beam:9494",
       "api_key":"dev-key","webhook_secret":"whsec-dev","enabled":true}'
```

`POST /api/v1/admin/servers/{id}/sync` enqueues a `beam_sync` job; watch it in
`GET /api/v1/admin/jobs`. Once it completes, `GET /api/v1/media/{id}/availability`
reports the item as available with deep links.

## Production deployment

Run compose *without* the `dev-idp` profile so the bundled Dex never starts,
and point `WW_OIDC_*` at your own provider:

```bash
export WW_TMDB_API_KEY=...
export WW_OIDC_ISSUER=https://auth.example.com
export WW_OIDC_CLIENT_ID=stacks
export WW_OIDC_CLIENT_SECRET=...
export WW_OIDC_REDIRECT_URI=https://stacks.example.com/auth/callback
export WW_ADMIN_EMAILS=you@example.com

docker compose up -d          # no --profile, so no Dex
```

The web container serves the built SPA on port 3000 and proxies `/api` to the
API container, so the browser only ever talks to one origin. Put a TLS reverse
proxy (Caddy, Nginx, Traefik) in front of port 3000.

The API serves its reference at `/api/docs` (Scalar) and its OpenAPI 3.1
document at `/api/openapi.json`; the same document is committed as
`web/openapi.json`.

See [`docs/DEPLOY.md`](docs/DEPLOY.md) for the full production guide.

## Configuration

All settings come from environment variables, optionally layered over a
`config.toml` whose path is taken from `WW_CONFIG_FILE` (default `config.toml`
in the working directory). Env vars take precedence over the file; required
values must be set somewhere or the API refuses to start.

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `WW_DATABASE_URL` | yes | — | PostgreSQL DSN (e.g. `postgres://user:pass@host:5432/db`). |
| `WW_TMDB_API_KEY` | yes | — | Passed to cameo for TMDB access (v3 key or v4 bearer). |
| `WW_METADATA_CONNECT_TIMEOUT_SECS` | no | `3` | Connect timeout for each TMDB / AniList request attempt. |
| `WW_METADATA_REQUEST_TIMEOUT_SECS` | no | `10` | Whole-request timeout for each TMDB / AniList request attempt. A failing provider falls back to the stored catalog snapshot. |
| `WW_OIDC_ISSUER` | yes | — | OIDC provider base URL; discovery uses `<issuer>/.well-known/openid-configuration`. |
| `WW_OIDC_CLIENT_ID` | yes | — | OIDC client id. |
| `WW_OIDC_CLIENT_SECRET` | yes | — | OIDC client secret. |
| `WW_OIDC_REDIRECT_URI` | yes | — | Redirect URI registered with the provider — the **web app's** `/auth/callback`, e.g. `http://localhost:3000/auth/callback`. The SPA forwards the code to the API. |
| `WW_OIDC_INTERNAL_ISSUER` | no | — | Server-to-server base URL for the same provider, when the API reaches it at a different address than the browser does (containers, reverse proxies). Discovery and token exchange use it; the browser-facing authorization URL is rewritten back onto `WW_OIDC_ISSUER`. |
| `WW_ADMIN_EMAILS` | no | — | Comma-separated emails provisioned as `admin` on login. Existing accounts are promoted on next sign-in. Without at least one, no account can reach `/api/v1/admin/*` — including streaming-server registration. |
| `WW_BIND` | no | `0.0.0.0:8095` | Listen address of the API. |
| `WW_METRICS_BIND` | no | `0.0.0.0:9095` | Listen address of the operator listener serving `/metrics` (Prometheus text format). Empty disables it. Expose it to Prometheus only. |
| `WW_METRICS_TOKEN` | no | — | When set, `/metrics` requires `Authorization: Bearer <token>`. |
| `WW_SESSION_TTL_SECS` | no | `2592000` | Lifetime of a sign-in session (30 days). Sessions are server-side rows; signing out or revoking one takes effect at once. |
| `WW_TRUSTED_PROXY_HOPS` | no | `1` | How many reverse proxies in front of the API append to `X-Forwarded-For` (the web container's nginx is one). The rate limiter keys on the client address they report. |
| `WW_RATE_LIMIT_PER_MINUTE` | no | `600` | Requests one client may make to `/api/v1` per minute. |
| `WW_LOG_LEVEL` | no | `info` | Subscriber filter — anything `tracing_subscriber::EnvFilter` accepts (`trace`, `debug`, `info`, `warn`, `error`, `module=level,...`). |
| `WW_DATA_DIR` | no | `/data` | Base directory; also the parent of the default cameo cache directory. |
| `WW_CAMEO_CACHE_DIR` | no | `${WW_DATA_DIR}/cameo` | Cameo cache directory. Note: cameo's response cache feature is currently disabled in the workspace; this path is reserved for when it is re-enabled. |
| `WW_CORS_ALLOWED_ORIGINS` | no | — | Comma-separated origins allowed to call the API from a browser, with credentials. Empty (the default) answers no cross-origin request, which is right when the web app reaches the API through its own origin, as the compose stack does. `*` is refused: sessions are cookies. |
| `WW_CONFIG_FILE` | no | `config.toml` | Optional TOML config path layered under env vars. |

The authoritative list lives in [`core/src/config/env.rs`](core/src/config/env.rs).

## API examples

The whole API is described by its OpenAPI 3.1 document, committed as
[`web/openapi.json`](web/openapi.json) and served by every running API at
`/api/openapi.json`, with an interactive reference at `/api/docs`. Everything
is under `/api/v1`. Errors are RFC 9457 problem documents
(`application/problem+json`) whose `type` links to
[ADR 0006](docs/adr/0006-error-model.md).

### Signing in

The web app signs in through OpenID Connect and ends up with an httpOnly
session cookie; JavaScript never sees a credential.

1. `POST /api/v1/auth/oidc/authorizations` returns `{ "authorization_url":
   "…" }`. The `state`, nonce and PKCE verifier stay on the server.
2. The browser follows it, signs in, and the provider redirects back to the
   web app's `/auth/callback?code=…&state=…`.
3. The web app posts `{ "code": "…", "state": "…" }` to
   `POST /api/v1/sessions`. The API verifies the id_token (signature,
   issuer, audience, nonce), answers `201` with the account, and sets the
   `stacks_session` cookie.

`GET /api/v1/sessions/current` says who is signed in; `DELETE
/api/v1/sessions/current` signs out.

### Scripts: API tokens

Create a token from a signed-in browser (`POST /api/v1/me/api-tokens` with
`{ "name": "backup", "scopes": ["read"] }`); its secret is in that response
only. Send it as a bearer credential:

```http
GET /api/v1/library?status=watching HTTP/1.1
Authorization: Bearer stk_…
```

A token needs `read` to read, `write` to change anything, and `admin` (an
administrator's token only) for `/api/v1/admin/*`; otherwise the answer is a
403 `insufficient-scope`.

### Search, then track

```http
GET /api/v1/search?q=reply%201988&category=k-drama HTTP/1.1
```

```json
{
  "items": [
    {
      "ref": "tmdb:show:64010",
      "title": "Reply 1988",
      "original_title": "응답하라 1988",
      "kind": "show",
      "category": "k-drama",
      "year": 2015,
      "library": null
    }
  ],
  "next_cursor": "Mg",
  "degraded": [],
  "unreadable": 0
}
```

Every title is named by its reference (`tmdb:movie:550`, `anilist:show:21`).
Put it in the library, then log what you watched:

```http
PUT /api/v1/library/tmdb:show:64010 HTTP/1.1
Content-Type: application/json

{ "status": "watching", "score": null, "favourite": false, "notes": null }
```

```http
POST /api/v1/library/tmdb:show:64010/plays HTTP/1.1
Content-Type: application/json

{ "kind": "through", "season": 1, "episode": 5 }
```

A play is undone with `DELETE /api/v1/plays/{id}`, which voids it and keeps
the record. Collections take `?cursor=…&limit=…` and answer
`{ "items": [...], "next_cursor": … }`; a cursor the server did not issue is
a 400.

When TMDB or AniList is down, a title read falls back to the stored snapshot
(`freshness.stale: true`), a listing names the failed provider in
`degraded`, and only a read with nothing to fall back on is a 502/503.

## Troubleshooting

- **`missing required environment variable: WW_DATABASE_URL`** (or
  `WW_TMDB_API_KEY`, any `WW_OIDC_*`). The API refuses to start without these.
  Set them in the environment or in a `config.toml` (see the configuration
  table).
- **Sign-in answers 400 `sign-in-failed`.** The authorization request expired
  (10 minutes), the callback was submitted twice, or the id_token failed
  verification (the API logs which). Start again from the sign-in button.
  Pending requests live in the database, so they survive restarts; a
  `just nuke` clears them.
- **Sign-in answers 502 `identity-provider-unavailable`.** The API could not
  reach the provider's discovery document, key set or token endpoint.
- **Login redirects to a provider the API cannot reach** (or vice versa) in
  containers. Set `WW_OIDC_INTERNAL_ISSUER` to the address the *API* uses while
  `WW_OIDC_ISSUER` stays the address the *browser* uses.
- **403 `insufficient-scope` from `/api/v1/admin/*`.** Your account is not an
  admin. Add its email to `WW_ADMIN_EMAILS` and sign in again, or have an
  existing admin call `PATCH /api/v1/admin/users/{id}` with
  `{ "role": "admin" }`.
- **`failed to install the Prometheus recorder`.** The process tried to
  install the global recorder twice. Make sure you are not running another
  stacks-api instance in the same process; this is a startup-only failure.
- **401 from every authenticated route.** The session expired or was ended
  (signing out, or `DELETE /api/v1/sessions/{id}` elsewhere), or the API token
  was revoked or expired. Sign in again, or create a new token.
- **403 `credential-store-unavailable`.** The API could not reach PostgreSQL to
  check the credential. Your session is fine; retry once the database is back.
- **CORS errors from the web app.** The composed stack serves the SPA and
  proxies `/api` from the same origin, so CORS should not apply. If you host the
  two separately, set `WW_CORS_ALLOWED_ORIGINS` to your frontend origin (with
  cookies, a wildcard is refused).
- **429 from `/api/v1`.** Each client may make `WW_RATE_LIMIT_PER_MINUTE`
  requests a minute (600 by default). Behind more than one reverse proxy, set
  `WW_TRUSTED_PROXY_HOPS`, or every client shares the proxy's bucket.
- **Migrations failed at startup.** Check the PostgreSQL version (>=18) and
  that the role in `WW_DATABASE_URL` can `CREATE TABLE`. Migrations run via
  `migration::Migrator::up`.
